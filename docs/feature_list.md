| AGT-09 | 保存成功提示 | 修改角色配置点击保存后，在上方弹出滑动提示“已保存” | P2 | ✅ 已实现 | 使用 Toast 提示 |
| AGT-10 | 双人设配置 | 每个 角色 独立维护「详细人设」（自身 System Prompt）和「简易人设」（给其他 角色 看的简介），均支持用户编辑 | P0 | ✅ 已实现 | 是 Prompt 拼接的核心数据来源 |

## 模块4：聊天核心

| 功能编号 | 功能名称 | 功能描述 | 优先级 | 状态 | 备注 |
|---------|---------|---------|--------|------|------|
| CHAT-01 | 用户发送消息 | 用户在输入框输入文本并发送，消息展示在聊天区域 | P0 | ✅ 已实现 | 支持 Enter 发送，Shift+Enter 换行 |
| CHAT-02 | 角色 回复消息 | 角色 接收上下文后调用 LLM API 生成回复 | P0 | ✅ 已实现 | 有"正在输入中"提示，回复完成后展示 |
| CHAT-03 | 消息气泡展示 | 按发送者区分展示消息气泡，支持时间戳、头像 | P0 | ✅ 已实现 | 类似微信/QQ 的聊天气泡 |
| CHAT-04 | 聊天记录滚动与加载 | 聊天区域支持滚动查看历史消息，支持跳转到最新消息 | P0 | 🚧 部分实现 | 基本滚动已实现，分页加载待完善 |
| CHAT-05 | 群聊 角色 自动触发 | 群聊禁言关闭后，任何角色发送消息会自动触发群聊中其它 角色 的调用；群聊消息达到上限后强制停止 | P0 | 🚧 部分实现 | 后端逻辑已支持，群聊 UI 待完善 |
| CHAT-06 | 用户介入 角色 对话 | 用户在 角色 自动对话过程中可随时发送消息参与 | P0 | ✅ 已实现 | 用户消息进入上下文，正常触发其它 角色 |
| CHAT-07 | 消息复制与重新生成 | 支持复制消息内容，对 角色 消息支持"重新生成" | P1 | ⬜ 待实现 | 重新生成替换原消息或插入新消息 |
| CHAT-08 | 消息引用/回复 | 支持引用某条消息进行针对性回复 | P1 | ⬜ 待实现 | 长按或右键菜单 |
| CHAT-09 | 聊天上下文管理 | 支持查看当前会话的系统提示词拼接逻辑，支持清空上下文 | P1 | ⬜ 待实现 | 技术用户可查看原始 Prompt |
| CHAT-10 | send_message Tool | 为 角色 提供 Function Calling 工具 `send_message`，参数含目标类型、目标 ID、内容，调用成功后不返回结果给 角色 | P0 | ✅ 已实现 | 不支持 Tool Calling 的模型无法配置 |
| CHAT-11 | 私聊自动触发 | 私聊中任何角色（用户或 角色）发送消息后，触发接收方 角色 的调用；私聊消息达到上限后强制停止 | P0 | ✅ 已实现 | 两个 角色 私聊时受全局最小间隔控制，避免高频循环 |
| CHAT-12 | 可见消息历史维护 | 为每个 角色 独立维护其可见的全部消息历史，按「私聊对象」和「群聊」分组 | P0 | ✅ 已实现 | Prompt 拼接时按此结构注入 |
| CHAT-13 | 全局最小触发间隔 | 每个 角色 拥有全局最小触发间隔（默认 30s），间隔内积压的所有新消息一次性组装调用 | P0 | ✅ 已实现 | 适用于所有私聊和群聊触发场景 |
| CHAT-14 | 消息上限配置 | 私聊和群聊分别可配置 角色 消息条数上限（不含玩家消息），达到上限后强制停止触发；默认开启，支持关闭 | P0 | ✅ 已实现 | 私聊默认 20 条，群聊默认 30 条 |
| CHAT-15 | 乐观消息展示 | 用户发送消息后，消息气泡应立即出现在聊天框中（无需等待后端响应） | P0 | ✅ 已实现 | 避免用户误以为发送失败 |
| CHAT-16 | LLM Provider 兼容性 | OpenAI-compatible Provider 需兼容 Minimax 等国内厂商（至少包含一个 user message） | P0 | ✅ 已实现 | Minimax 要求请求体中不能只有 system message，已自动处理 |
| CHAT-17 | LLM 错误提示优化 | LLM 调用失败时不使用 alert 弹窗，改用可关闭的 Toast；取消重试机制避免多次报错 | P1 | ✅ 已实现 | Toast 通知替代 alert，错误保留便于调试 |
| CHAT-18 | 重试机制控制 | 移除 LLM 的 3 次重试逻辑，失败一次即停止并提示用户 | P1 | ✅ 已实现 | 减少 API 调用成本和用户干扰 |

## 实现顺序建议（已更新）

1. **阶段一：角色 配置 + UI（已完成）**
   - 角色 的创建、编辑、双人设配置、模型 API 配置、强制 Tool Calling 检测、角色 列表 UI
   - 应用基础框架和本地数据存储（强制便携模式）

2. **阶段二：用户与 角色 的 1对1 对话（已完成）**
   - 私聊会话创建、消息收发、好友关系建立
   - Prompt 拼接逻辑（含好友/群友筛选）
   - `send_message` Tool 接入
   - 全局最小触发间隔、私聊消息上限
   - **Bug 修复**：UTF-8 安全截断、is_triggering 死锁防护

3. **阶段三：群聊（后端已完成，UI 待完善）**
   - 群聊创建、禁言开关 UI
   - 群聊中的多 角色 自动触发逻辑
   - 群聊消息上限、简易人设同步、可见消息历史维护

4. **V1.1（待排期）**
   - 安装包构建（APP-01）、数据备份恢复（APP-04）
   - 会话管理增强：置顶、归档、搜索、设置
   - 消息重新生成、上下文查看、主题切换
   - API 连通性测试、头像上传

5. **V2.0（待排期）**
   - 用户角色扮演系统（USR-01~04）
   - 图片/文件消息支持
