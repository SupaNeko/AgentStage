# AgentStage 功能使用指南

本文档按功能模块介绍 AgentStage 的核心用法，帮助用户快速上手多智能体角色扮演聊天。

---

## 1. 创建角色与模型配置

### 1.1 创建角色

点击角色列表页的「新建」按钮，进入角色创建流程：

- **角色名称**：角色的显示名称（1-20 字符）
- **头像**：支持上传本地图片（自动压缩为 WebP）
- **详细人设**：角色自身的完整设定（System Prompt），决定性格、语气、行为方式
- **简易人设**：给其他角色看的「名片」，让对方知道「我是谁」

### 1.2 AI 辅助生成人设（重点功能）

如果你不想从零开始写人设，可以使用**人设自生成**功能：

1. 在创建/编辑角色页面，展开「人设自生成」区域
2. 填写**参考角色**（如"远坂凛"）或**补充信息**（如"性格高冷、说话带刺的魔法少女"）
3. 配置好下方的模型和 API Key（用于调用 LLM 生成）
4. 点击「生成」，系统会自动调用大模型为你生成：
   - 详细人设
   - 简易人设
   - 性格标签、场景设定、示例对话等辅助字段

> 💡 **提示**：生成质量取决于你提供的参考信息和模型能力。可以先写一个粗略描述，让 AI 帮你扩展成完整人设。

### 1.3 模型配置

每个角色可以独立配置调用的 LLM 服务：

| 配置项 | 说明 |
|--------|------|
| 模型提供商 | OpenAI / Anthropic / Google / Kimi / MiniMax / 自定义 |
| 模型名称 | 如 `gpt-4o`、`kimi-k2`、`claude-3-5-sonnet` |
| Base URL | 选择厂商后**自动填充**默认值，也可手动修改为自定义端点 |
| API Key | 直接填写，支持点击眼睛图标切换明文/密文显示 |
| Temperature / Max Tokens | 控制生成随机性和最大长度 |
| 思考模式 | 启用模型的推理模式（如 Kimi k2、DeepSeek Reasoner） |

> ⚠️ **重要备注：部分模型供应商的 Coding Plan 会校验客户端身份，导致无法使用。**
>
> **解决方法**：更换为支持 OpenAI 兼容格式调用的计划（如标准 API 计划、开发者计划），或使用中转/代理服务（如 OneAPI、New API）转发请求。

**便捷功能**：
- **测试连接**：填写 API Key 后，点击右侧「测试连接」按钮，可即时验证 API 可用性并显示延迟
- **从其他角色导入**：点击「从其他角色导入」，可一键复制已有角色的完整模型配置（含 API Key）

## 2. 用户人设系统

### 2.1 创建用户人设

进入「我的人设」页面，点击「新建人设」：

- **角色名**：你在会话中使用的身份名称（如"Tom"）
- **简易人设**：描述你的身份、性格、与其他角色的关系等
- **头像**：该人设专属头像

你可以创建多个人设，用于不同会话场景。

### 2.2 人设的作用

当你**启用了某个人设**后，该人设信息会被注入到**当前会话所有角色**的 System Prompt 中：

```
- Tom（真实用户）：一位来自异世界的旅行者，性格开朗，正在寻找回家的路。
```

这意味着：
- 角色知道「你是谁」，而不仅仅是「有个用户在说话」
- 不同会话可以使用不同身份，角色对你的认知随之变化
- 角色会根据你的人设调整说话方式和态度

### 2.3 切换人设的影响

- **即时生效**：切换后，新发送的消息会以新人设身份展示
- **历史不变**：已发送的消息不会 retroactively 改变身份
- **角色认知更新**：后续触发角色时，Prompt 中会注入新人设信息

> 💡 **默认状态**：如果没有启用任何人设，角色眼中的你就是「正在与你聊天的真实用户」。

## 3. 发起会话与创建群聊

### 3.1 发起 1 对 1 私聊

在角色详情页点击「开始聊天」，或在左侧会话列表点击「新建会话」选择角色：

- 如果与该角色的私聊**已存在**，会自动跳转到已有会话
- 如果**不存在**，会创建新的私聊会话

私聊中，任何一方发送消息后，对方角色会在满足触发条件时自动回复。

### 3.2 创建群聊

点击「新建会话」→ 选择「群聊」：

- **群聊名称**：必填，如"三剑客讨论组"
- **群头像**：可选
- **选择角色**：至少选择 2 个角色（加上你自己，群内至少 3 人）
- **禁言开关**：新建群聊默认**开启禁言**

**群聊互动机制**：
- **禁言开启**：群聊表现为普通 IM 群，只有你发消息，角色不会自动发言
- **禁言关闭（自动模式）**：任何消息都会触发群内**其他所有角色**的自动调用，它们会根据上下文决定是否回复

> ⚠️ **注意**：群聊中角色可能选择不回复（就像真实群聊中不是每条消息都有人回应），这符合自然互动节奏。

## 4. 重置会话的意义

### 4.1 什么是重置会话

在会话配置面板中点击「重置会话」，系统会：

1. 保留当前会话成员不变
2. 创建一个新的聊天页（chat_page）
3. 清空当前页的历史消息和未读状态
4. 以相同成员开启**全新的上下文**

### 4.2 重置的使用场景

| 场景 | 说明 |
|------|------|
| 剧情分叉 | 聊到某个关键节点，想尝试不同的剧情走向 |
| 上下文过长 | 角色记忆混乱，想清空历史重新开始 |
| 实验人设 | 修改了角色人设后，想用新设定开启新对话 |
| 多线叙事 | 同一个角色组，在不同情境下展开多条故事线 |

> 💡 **与删除会话的区别**：删除会话是软删除（会话从列表消失），聊天记录保留在数据库中；重置会话是保留会话本身，清空当前页消息并开启新页。

## 5. 配置与限制

### 5.1 会话级配置

在每个会话的配置面板中，可以调整：

#### 消息上限（自动消息限制）

- **私聊**：对方角色发送的消息达到上限后，自动停止触发
- **群聊**：群内所有角色发送的消息总和达到上限后，自动停止触发
- 达到上限后，**你发送任意消息即可重置计数**，恢复自动对话
- 也可手动关闭上限或调高数值

#### 禁言开关

- 开启后，该会话内**不再自动触发任何角色**
- 你发送的消息仅被记录，不会引起角色回复
- 适用于：只想旁观、手动控制节奏、暂停剧情

#### 历史提示条数

- 控制角色在 Prompt 中能看到该会话的最近 N 条消息
- 调低可减少 Token 消耗，调高可保留更长上下文

### 5.2 全局调用 CD（最小触发间隔）

在「设置」面板中，可以配置**全局最小触发间隔**（默认 30 秒）：

- 每个角色拥有独立的全局计时器，**跨所有会话共享**
- 间隔内到达的所有消息会被**积压**，到期后一次性处理
- 效果：
  - 大幅降低 API 调用频率和费用
  - 角色会像真实人类一样「看完几条消息后一起回复」
  - 不同角色有各自的反应节奏，避免秒回轰炸

> 💡 如果你希望角色响应更快，可以将间隔调小（最低 5 秒）；如果希望更省 API 费用，可以调大（最高 300 秒）。
